# Evaluation

How answer quality is measured, the CI gate built on it, and the results.
The full retrieval comparison is in
[retrieval-benchmark.md](retrieval-benchmark.md).

## Golden set

[`evals/golden_set.yaml`](../evals/golden_set.yaml) has 30 hand-written
questions over the three 10-Ks:

| Category | Count | Example shape |
|---|---|---|
| factual | 12 | one fact from one filing |
| comparative | 8 | company A vs company B on one metric |
| temporal | 5 | the change between fiscal years |
| **unanswerable** | **5** | genuinely absent from the corpus; the system must decline, not guess |

Every ground truth was written from the filing text, not generated by the
model under test, and lists the page it comes from, so each one can be
checked against the PDF. For comparisons, each company's own answer page
must be retrieved ("page hit" per source).

## Harness

For each question, `evals/run.py`:
1. retrieves once (top-8, with the question's company filter);
2. answers once, from exactly those chunks;
3. scores the result.

| Metric | By | What it checks |
|---|---|---|
| context precision, context recall | RAGAS 0.4 | whether the retrieved chunks are relevant, and whether they contain the answer |
| faithfulness | RAGAS 0.4 | whether every claim in the answer is supported by the context |
| answer relevancy | RAGAS 0.4 | whether the answer addresses the question |
| citation validity | Python | cited ids ⊆ retrieved ids |
| abstention / false abstention | Python | declines unanswerable questions; doesn't decline answerable ones |
| expected page retrieved | Python | the ground truth's page is among the retrieved chunks, for every source |
| latency, cost/query | Python | p50/p95 per stage; tokens priced from [`evals/pricing.yaml`](../evals/pricing.yaml) |

RAGAS runs in its own uv environment ([`evals/ragas/`](../evals/ragas/)),
because it needs `openai<3` and the app uses openai 3.x. The harness calls
it as a subprocess.

```bash
uv run python -m evals.run [--variant vector|hybrid|hybrid_semantic]   # all 30 → results/
uv run python -m evals.run --smoke          # 5 questions, production mode; exits 1 below the thresholds
uv run python -m evals.run --smoke --trace  # also send traces to Langfuse
uv run python -m evals.reconcile results/<run>.json   # compare the harness's cost with Langfuse's
```

## The CI gate

`--smoke` runs 5 questions (2 factual, 1 comparative, 1 temporal, 1
unanswerable) in the production retrieval mode. It fails the pipeline if:
- faithfulness is below **0.90**;
- citation validity is below **0.80** (one malformed id is tolerated; two
  fail);
- the unanswerable question is answered (abstention must be **1.0**);
- any score is missing or NaN.

Thresholds and the measurements behind them are in
[`evals/thresholds.yaml`](../evals/thresholds.yaml) (D-44, D-57).

## Results

**Retrieval benchmark** (all 30 questions, same day and same index):

| variant | context precision | context recall | false abstention | abstention (unanswerable) | page hit | retrieval p50 | cost/query |
|---|---|---|---|---|---|---|---|
| vector | 0.542 | 0.847 | 16% | 100% | 76% | 539 ms | $0.0017 |
| hybrid (BM25 + vector, RRF) | 0.592 | 0.947 | 4% | 100% | 76% | 536 ms | $0.0015 |
| **hybrid + semantic ranker** (shipped) | **0.806** | **1.000** | **0%** | 100% | **100%** | 592 ms | $0.0015 |

- **Shipped:** hybrid + semantic ranking. It retrieved the expected evidence
  for every answerable question, at about +55 ms median retrieval latency.
- **Abstention held in every variant:** all of them declined every
  unanswerable question. Better retrieval didn't make the system more willing
  to guess.
- **Faithfulness:** 0.97–0.99 across the variants.
- **Citation validity:** 100% in every variant.

The analysis is in [retrieval-benchmark.md](retrieval-benchmark.md).

## How to read these numbers

- **The judge is the model being judged.** RAGAS uses the same gpt-5-mini
  deployment that writes the answers, so read the RAGAS figures as
  comparisons between variants, not absolute scores.
- **Run-to-run noise is about ±0.05** on the RAGAS metrics. The benchmark's
  gains are several times larger than that.
- **The eval isolates the retriever:** each question is given its company
  filter, whereas in the real system the planner picks companies itself.
